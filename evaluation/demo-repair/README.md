# Demo repair evidence

This directory freezes the 2024 homepage Roboflow response before changing candidate selection. The model response was obtained on 2026-09-28 from the bundled 1024-pixel image with the same 20% inference floor as the app. `sample-roboflow.json` preserves all 27 raw predictions. The deterministic app deduplication retains 22 from this response; browser JPEG re-encoding can change that count slightly.

The two regions the user called visibly fan-like in the live page correspond to the center deposit (raw index 0) and lower-right deposit (raw index 11). The old selection also showed a seven-pixel speck. These are visual development examples, **not expert fan labels**. The local M3/MLX comparison in `local-jev-view-comparison.json` uses the old mask-only prompt and the new region-context prompt on the three featured regions. The hosted CUDA comparison is in `hosted-jev-view-comparison.json`; the exact pixels sent to the model are in `gallery/`. The old masked instruction rejected all three selected sample regions, while the new region-context instruction called all three Fan. Warm hosted calls took 0.2–0.4 seconds wall time after the first call.

That does **not** establish classification accuracy. Three visual non-fan terrain probes from the newer observation were also called Fan, even with a stricter question (`hosted-negative-probes.json`, `hosted-prompt-probes.json`). A prompt/overlay factorial check (`hosted-factorial-probes.json`) shows the result is strongly sensitive to question wording. On the six existing locked crops, Jev called **all 17 tested featured candidates Fan**, including three without a nearby pre-marked clear deposit (`hosted-locked-probes.json`). Those three are not expert negatives, but the all-Fan pattern is a strong warning against treating these scores as a reliable classifier. Jev suggestions remain advisory. No threshold on the small positive/terrain probe cleanly separates the fan-like examples from the non-fan terrain.

The existing `../locked/` six-crop set from ESP_082241_0950 supplies 16 pre-marked clear fan-like centers and frozen detector responses. `holdout/` contains three crops selected from an overview of a different observation, ESP_092344_0970, before running the detector there. This 2025 observation has different visual texture; its crops are not expert-labeled and must not be treated as a positive-fan test. The first holdout crop is also saved at native two-times resolution to compare faint edges before and after the app's downsampling. The current segmentation detector produced 71, 75, and 24 raw proposals on these crops; the selected regions visibly track rocky ridges and shadows (`holdout/*.featured.jpg`). This is a hard-negative stress test showing poor domain transfer, not a formal false-positive rate.

Run `node scripts/report_demo_repair.mjs` to rebuild `candidate-report.json`. The report measures selection size and proximity to the existing non-expert marks; it does not measure mask boundary quality. `scripts/report_holdout.mjs` rebuilds the three holdout selection overlays and counts from the frozen responses. A separate Roboflow object-detection comparator, [Mars Fan Box Proposals v1](https://app.roboflow.com/matt-abrams/mars-fan-box-proposals/1), uses boxes converted from the original weak masks at 1024 pixels. It is an experiment, not a corrected-label model, and must be compared with the current segmentation model before any promotion. The 24-chip pending review queue and rules are in `annotation-queue.json` and `ANNOTATION_GUIDE.md`; a replacement segmentation training run still requires complete, corrected fan masks.
